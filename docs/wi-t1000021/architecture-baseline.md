# 客户跟进管理应用 · 架构基线

- 工作项：wi-t1000021
- 阶段：design
- 版本：v1
- 路线：simple-frontend（compact）
- 需求基线：`docs/wi-t1000021/requirements.md`（sha256:6159b6fbb5f8582cbace22defe6b3b3ebb76ef61674d2f11343d36f97a85f217）

## 1. 应用形态与技术选型

单用户、纯浏览器端的 React 单页应用（SPA），使用 Vite 作为构建与开发工具链。无服务端、无数据库、无认证、无后台任务、无外部服务集成、无跨用户/设备同步层；全部业务数据保存在浏览器内存状态中。此选型直接承载需求 §2「本地状态管理（内存状态，非服务端存储）」与 §5 S1 的数据归属约定。

## 2. 页面与交互范围

应用由三个视图组成，对应需求 §4 的三个模块：

- **客户列表**：展示预置客户，支持按名称关键词搜索、按标签筛选、按销售阶段筛选，三种条件可组合生效，清除后恢复完整列表。
- **销售阶段看板**：按销售阶段分列展示客户卡片，支持将卡片拖拽到目标阶段列以切换该客户的销售阶段。
- **客户详情页**：展示客户基本信息与当前阶段，提供新增跟进记录入口、设置下次联系时间与负责人，并以时间线按时间展示历史沟通记录。

三个视图共享同一份应用状态，任一视图的修改在同一会话内立即同步到其他视图（需求 §5 S2）。

## 3. 数据与状态归属

- **权威状态**：全部业务数据（客户、销售阶段、标签、跟进记录、负责人、下次联系时间）保存在 React 应用的内存状态树中，由应用自身负责读写，不经过任何服务端或持久化层。
- **初始化**：应用启动时用一组内置预置客户数据初始化状态，使列表、看板、详情页开箱可用（需求 §4.1 L1）。
- **刷新行为**：刷新或重新打开页面后，状态重新初始化为预置数据，会话内的修改不保留。此行为忠实于需求 §2「刷新页面后恢复初始预置数据」与 §6「跨会话持久化不要求」，因此本基线不引入 `localStorage` 或其他持久化机制。
- **跨视图同步**：状态提升到应用根层，由根状态向下分发；列表、看板、详情页读写同一状态源，保证同一会话内实时一致。

## 4. 实现入口与运行方式

- **实现入口**：应用根目录下的 Vite + React 工程，入口为 Vite 约定的 `index.html` 与 `src/main.tsx`（或 `src/main.jsx`）；应用根组件挂载三个视图的路由或视图切换。
- **运行方式**：新建 Vite 工程，使用 Vite 开发服务器本地运行；若选用 npm，则 `npm install` 后执行 `npm run dev`，在浏览器访问开发服务器输出的本地地址即可使用。

## 5. 明确的非目标

本基线不引入也不预留：服务端/API、数据库、认证与权限、后台任务、外部服务集成、跨设备或跨用户同步、数据导出与统计报表。这些均不在需求范围内（需求 §6），实现不必补全。
