# 客户跟进管理应用 · 需求文档

- 工作项：wi-t1000021
- 阶段：requirements
- 版本：v1

## 1. 目标

用户明确提出：开发一个"客户跟进管理"React 应用，围绕客户管理销售跟进过程。应用包含三个核心视图：客户列表、销售阶段看板、客户详情页，数据使用本地状态管理。

核心用户结果：

- 在客户列表中快速定位目标客户（搜索、标签、阶段筛选）；
- 在看板上通过拖拽推进客户的销售阶段；
- 在客户详情页记录沟通历史、设置下次联系时间与负责人。

## 2. 范围与约束

| 项 | 内容 | 来源 |
| --- | --- | --- |
| 应用形态 | React 应用，浏览器用户界面 | 用户明确提出 |
| 数据管理 | 本地状态管理（内存状态，非服务端存储） | 用户明确提出 |
| 会话行为 | 同一会话内各视图数据实时同步；刷新页面后恢复初始预置数据 | 用户明确提出（本地状态管理的直接结果） |
| 核心视图 | 客户列表、销售阶段看板、客户详情页 | 用户明确提出 |

## 3. 核心场景

**场景 A · 查找客户**：用户打开应用，在客户列表中通过关键词、标签、阶段筛选定位目标客户，并进入其详情页。

**场景 B · 推进阶段**：用户在看板上把客户卡片拖到目标销售阶段列，完成阶段推进；客户列表与详情页的阶段信息同步更新。

**场景 C · 记录与规划**：用户在客户详情页新增跟进记录，记录立即出现在时间线；同时设置下次联系时间和负责人，支撑后续跟进安排。

## 4. 模块需求

### 4.1 客户列表

- L1 展示全部预置客户（推荐基线：应用内置一组示例客户数据，使列表、看板、详情页开箱可用）。
- L2 搜索：按客户名称关键词过滤（推荐基线：搜索范围为客户名称）。
- L3 标签筛选：按客户标签过滤（标签取值未规定，由预置数据携带）。
- L4 阶段筛选：按销售阶段过滤。
- L5 三种筛选可同时生效、组合过滤（推荐基线：由"支持搜索、标签和阶段筛选"闭合的最小行为）；清除筛选后恢复完整列表。

### 4.2 销售阶段看板

- K1 按销售阶段分列展示客户，每列一个阶段（推荐基线：阶段序列为"初步接触 → 需求确认 → 方案报价 → 商务谈判 → 已成交"，共 5 列；阶段名称与数量为实现可调整的推荐值）。
- K2 拖拽客户卡片到目标阶段列，即把该客户的销售阶段切换为目标列阶段（用户明确提出）。
- K3 阶段切换在同一会话内同步反映到客户列表与客户详情页（用户明确提出"数据使用本地状态管理"的直接结果）。

### 4.3 客户详情页

- D1 可从客户列表或看板进入某客户的详情页（用户明确提出详情页存在；进入方式未规定，推荐从列表行或看板卡片点击进入）。
- D2 展示客户基本信息与当前销售阶段（用户明确提出）。
- D3 新增跟进记录：提供录入入口，提交后该记录立即可见于时间线（用户明确提出；推荐基线：记录至少包含沟通内容与记录时间）。
- D4 时间线：按时间展示该客户全部历史沟通记录（用户明确提出；推荐基线：最新记录在前）。
- D5 设置下次联系时间（用户明确提出；形式未规定，推荐日期形式）。
- D6 设置负责人（用户明确提出；取值来源未规定，推荐文本形式录入）。
- D7 详情页设置的下次联系时间与负责人在同一会话内保持，重新进入详情页可读回原值（用户明确提出"本地状态管理"的直接结果）。

## 5. 数据与状态规则

- S1 客户、跟进记录、销售阶段、标签、负责人、下次联系时间等业务数据均保存在应用本地状态中（用户明确提出）。
- S2 任一视图的修改（拖拽换阶段、新增记录、设置字段）在同一会话内立即同步到其他视图（用户明确提出）。
- S3 销售阶段模型见 K1（推荐基线）。

## 6. 未规定事项

以下缺口不影响核心验收，本基线不作规定，实现不必补全：

- 新增客户、删除客户、编辑客户基本信息：用户未提出，不在本基线。
- 标签与负责人的具体取值及来源：未规定。
- 跟进记录的沟通方式、内容格式等细节：未规定（最小构成见 D3 推荐基线）。
- 下次联系时间的到期提醒或通知能力：用户未提出。
- 数据导出、统计报表、多用户与权限体系：用户未提出。
- 跨会话持久化：用户明确选择本地状态管理，不要求（见 §2）。

## 7. 验收场景

### AC-01：用户可在客户列表按关键词、标签和阶段筛选客户

- 验收条件：客户列表提供搜索、标签筛选、阶段筛选三种过滤能力，可组合生效；结果仅显示同时满足全部生效条件的客户；清除筛选后恢复完整列表。
- 入口类型：用户界面
- 验证动作：打开应用进入客户列表；在搜索框输入当前列表任一客户名称的关键词，观察结果；再选择一个当前列表存在的标签，观察结果；再选择一个销售阶段，观察结果；依次清除搜索词、标签、阶段筛选，观察列表变化。
- 预期结果：仅输入关键词时，列表只显示名称匹配的客户；追加标签后，列表只显示同时匹配关键词与标签的客户；再选阶段后，列表只显示同时满足三个条件的客户；每清除一个条件，列表按剩余条件刷新；全部清除后显示全部预置客户。
- 证据类型：runtime-render, interaction

### AC-02：用户可通过拖拽将客户切换到其他销售阶段

- 验收条件：看板按销售阶段分列；把客户卡片拖到另一阶段列后，该客户阶段更新为目标列阶段；同一会话内列表与详情页的阶段信息同步更新。
- 入口类型：用户界面
- 验证动作：进入销售阶段看板，观察各阶段列的客户卡片；任选一个客户卡片，拖到另一个阶段列后松开，观察卡片位置；切换到客户列表，按目标阶段筛选；进入该客户详情页查看其销售阶段。
- 预期结果：拖拽后该卡片出现在目标阶段列，且不再出现在原阶段列；列表中按目标阶段可以筛出该客户；该客户详情页显示切换后的阶段。
- 证据类型：runtime-render, interaction

### AC-03：用户可在详情页新增跟进记录并通过时间线查看历史沟通

- 验收条件：客户详情页提供新增跟进记录的入口；提交后记录立即出现在时间线；时间线按时间展示该客户全部历史沟通记录。
- 入口类型：用户界面
- 验证动作：从客户列表或看板进入任一客户详情页，查看时间线中的历史沟通记录；使用新增跟进记录入口录入一条记录并提交，观察时间线；离开详情页后重新进入同一客户详情页。
- 预期结果：提交后新记录立即出现在时间线中；时间线按时间展示该客户的全部历史沟通记录；同一会话内重新进入详情页，新增记录仍然存在。
- 证据类型：runtime-render, interaction, session-persistence

### AC-04：用户可在详情页设置下次联系时间和负责人

- 验收条件：客户详情页可设置并保存下次联系时间与负责人；保存后详情页展示所设值；同一会话内重新进入详情页读回原值。
- 入口类型：用户界面
- 验证动作：进入任一客户详情页；设置下次联系时间；设置负责人；保存；离开详情页后重新进入同一客户详情页，查看两项设置。
- 预期结果：保存后详情页展示所设的下次联系时间与负责人；同一会话内重新进入详情页，两项设置保持不变。
- 证据类型：runtime-render, interaction, session-persistence
